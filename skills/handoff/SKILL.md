# Handoff: передача сессии артефактом

При завершении/обрыве/компакции сессии ПМ состояние разговора не существует —
существует только артефакт. Этот скилл превращает состояние в handoff-документ,
по которому следующая сессия продолжает работу без археологии.

## Когда

- Плановое завершение сессии (даже «на сегодня все»)
- Обрыв/компакция контекста — до того, как контекст ушел
- Передача работы другому инстансу (параллельный проект)

Не применять для: ретроспективы урока (это backlog/MAP), статуса релиза
(это PLAN.md) — handoff на них ссылается, не дублирует.

## Формат handoff-документа

`docs/handoffs/handoff-<дата>-<тема>.md` (append-only каталог):

1. **Состояние**: что происходит прямо сейчас (пакет/флоу/этап, последний
   завершенный шаг, последний PR/commit-hash).
2. **В полете**: запущенные делегации (id, роль, что вернут), фоновые
   процессы (gate, крон), незавершенные ревью.
3. **Дальше — по шагам**: точная следующая команда/действие (не «продолжить
   работу», а «смержить PR #N после зеленого flow»).
4. **Развилки/ожидания**: что и кого ждем (решение Заказчика, ответ БА).
5. **Ссылки**: артефакты (PLAN.md, MAP, review-файлы, PR) — путями, не
   пересказом.

## Правила

- Артефакты — путями, не пересказом: следующий агент читает источники сам.
- Незавершенное — честно «в полете/оборвано», не «почти готово».
- Handoff пишется ДО потери контекста: плановое завершение — за минуту до
  конца; обрыв поймать не можем — поэтому критичное состояние держится в
  PLAN.md непрерывно, handoff лишь срез.
- После обрыва/падения: следующая сессия начинает с чтения последнего
  handoff + PLAN.md + `git log` — не с попытки вспомнить.

## Инструмент (scripts/)

**`scripts/handoff_scaffold.py`** — скелет handoff-документа (Состояние /
В полете / Решения / Открытые вопросы / Следующий шаг) с датой и slug в имени.
Append-only: существующий файл скрипт не перезаписывает.

```bash
python skills/handoff/scripts/handoff_scaffold.py "передача p16 волна 2" --dir docs/handoffs
```
