2. **detect_conflict (`src/services/event.py:157-240`):**

Атака 5 подтвердила: ввод sleep ровно в момент сиротского wake → конфликт; минутой позже → конфликта нет (валидный порядок wake→sleep не ломается). Ложных расширений правила нет.

Тесты TC-CFL-004/005 ассертят выбор цели по id и содержимому остальных записей.
   - **Порядок:** соседи нового момента (`prev` — последний `ts <= t`, `next` — первый `ts > t`); конфликт, если сосед того же вида. Атака 1 (ввод ровно между двумя снами) и атака 7 (нормальная последовательность) — false positive нет, валидное чередование проходит.

## Собственные атаки (все выполнены против кода 29e4747, скрипт вне репо)

1. **Ввод времени ровно между двумя снами** (sleep −6, wake −4, sleep −2; ввод на −3ч): wake на −3ч → конфликт с wake −4ч; sleep на −3ч → конфликт с sleep −2ч (оба — корректные нарушения порядка, цели по D11). False positive на валидном чередовании нет (атака 7: sleep через час после wake проходит, wake внутрь интервала ловится).
2. **Конфликт + устаревший guard:** цель удалена «↩️ Отменить последнее» между показом §7.13 и нажатием «Изменить» → `rowcount = 0`, ни одной записи не создано/не изменено, исключения нет, фазы сняты, меню перерисовано. Данных-мусора нет.
3. **Двойное нажатие «Изменить»** (один context, два вызова подряд — как реальный двойной клик): нажатие 1 — перезапись + уведомление; нажатие 2 — no-op (фазы сняты → безопасный дефолт, `redraw_menu`), записей по-прежнему 1, дубля нет. Двойной перезаписи нет. (Первый вариант атаки с пересозданием фаз между нажатиями — некорректная модель двойного клика; отброшен.)
4. **Конфликт при незакрытом текущем сне:** открытый sleep −3ч, ввод wake на −1ч → конфликт с открытым сном (интервал до now, D9-семантика); «Изменить» атомарно превращает стартовую запись в wake — данных-дублей нет, результат детерминирован.
5. **Санкционированное правило точного совпадения на сиротском wake:** wake −2ч без предшествующего sleep; ввод sleep ровно в −2ч → конфликт (нужен, иначе нулевой зазор прошёл бы как валидный порядок); ввод sleep на минуту позже → конфликта НЕТ (правило не переусердствует). Оцениваю расширение корректным: без него сценарий §7.13 имел бы дыру именно на сиротском wake.
6. **Ничья по дистанции:** события в −3ч и −1ч, ввод на −2ч (дистанция 1ч до обоих) → цель — более раннее (sleep −3ч). Детерминизм D11 подтверждён.
7. **Ввод во внутренность записанного интервала vs после wake:** wake внутрь [−8;−2] → конфликт; sleep после wake → нет. Границы включены корректно.
