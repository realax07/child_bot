# Proposal: add-settings-history — настройки, история, справка (Пакет 3)

- **Флоу:** 1
- **Дата:** 2026-11-01
- **Автор:** СА
- **Источники:** `PLAN-add-settings-history.md` (план пакета 3, волны 1–4, решения); ТЗ «Дневник сна ребёнка» §5 (настройки) и §5.1 (settings_history), §4.8 (история), §4.4/§7.10–7.15 (ввод постфактум), §6 (меню — «📊 История за неделю» и «⚙️ Настройки» появляются), §7.16–7.22 (тексты настроек/истории), §7.26–7.28 (удаление, /help), §8.3/§9.4 (settings_history), §10.2–10.4 (команды/callback/FSM); `backlog/product-backlog.md` (PB-1, PB-2, PB-5, «Техдолг пакета 2»); design add-core-diary D1–D15, add-recommendations D16–D20

## Зачем (проблема)

Пакет 1 дал дневник, пакет 2 — советник, но «ручки» у пользователя нет: 13 параметров режима лежат в `settings`, seed'ятся при /start (D14) и не показываются и не меняются через интерфейс. Приемка 26.10: «нет никакой истории, она нигде не отображается» (PB-5); ввод задним числом спрашивает время одного события, хотя пользователь знает оба (PB-1); в диалоге ввода нет быстрых пресетов (PB-2). Нет справки /help и небезопасной чистки /delete_all из ТЗ §7.26–7.28. Без пакета не закрыты US блока E/F ТЗ (§11 Блок E «Подсказка сейчас», Блок F «История и настройки»).

## Что делаем (решение одной фразой)

Экран ⚙️ Настройки (§7.16, группы) с диалогом изменения §7.17–7.19, валидацией форматов и записью каждой смены в `settings_history` (§5.1/§8.3); кнопка «📊 История за неделю» — сводка за 7 дней + сегодня с отметками ✓/⚠️ (§7.20–7.22, PB-5, та же арифметика CalculationService); PB-1 — парный ввод задним числом (засыпание + пробуждение двумя шагами, единый конфликт-чек — решение продакта 01.11); /help (§7.28) и /delete_all с подтверждением отдельной кнопкой (§7.26–7.27, решение продакта 01.11). Пресеты времени (PB-2) — отменены продактом 01.11.

## Альтернативы (минимум 2, с trade-off)

1. **Настройки — UI над существующим SettingsService (расширение `src/services/settings.py` + новый экран в service/handler-слоях)** — trade-off: единый источник ключей DEFAULT_KEYS (13), запись в history рядом с update, тесты без Telegram; файлы растут. ✅ Выбрано (design D21; ТЗ §10.5 SettingsService.update/get_history).
2. Отдельный SettingsUI-сервис со своей копией ключей и валидаторов — trade-off: изоляция, но вторая копия списка параметров неизбежно разойдётся с seed'ом D14 (уже был инцидент с дублем дефолтов §5 в events.py — техдолг 2.3). Отклонено.
3. **История — агрегация недели чистой функцией CalculationService от сырых событий** — trade-off: та же арифметика BUG-004/склейки/страниц дня, что в фактах PB-3 и подсказках; без таблицы daily_summary. ✅ Выбрано (design D22; ТЗ §4.8).
4. **PB-1 — диалог из двух шагов («Когда заснул?» → «Когда проснулся?»)** — trade-off: на одно нажатие больше, но меньше ошибок формата и один конфликт-чек на пару; вариант «одним сообщением 13:40 15:15» — компактнее, но ломает существующий парсер форматов §4.4. ✅ УТВЕРЖДЕНО продактом 01.11 (ОВ-5.1: два шага; design D23).
5. Кнопки-пресеты времени (PB-2 вариант а) в диалогах ввода — trade-off: дёшево, но extra-кнопки в диалоге; ✅→❌ ОТМЕНЕНЫ продактом 01.11 (ОВ-5.2: «не думаю что пригодится») — из пакета исключены (design D24, FR-52 ОТКЛОНЕНО); Telegram Web App с календарём (вариант б) — anti-scope, этап 2+.

## Границы (anti-scope)

- Кнопки-пресеты времени (PB-2 вариант а) — ОТКЛОНЕНЫ продактом 01.11 (ОВ-5.2); в диалоге ввода остаётся «🕐 Сейчас» (§7.10).
- Telegram Web App / календарь-пикер времени (PB-2 вариант б) — этап 2+, по потребности.
- UI смены роли наблюдателя — не делаем (решение ПМ в PLAN; роль читается из users.role, доступ — D13 пакета 1).
- Миграции БД: `settings_history` — идемпотентное `CREATE TABLE IF NOT EXISTS` по ТЗ §9.4 в схеме `db.py` (таблица пустая, данных не лифтуем — отдельного миграционного шага нет).
- `settings:reset` (сброс настроек, ТЗ §10.3): в §5/§7 текста и в PLAN нет — вне пакета, отдельное решение ПМ.
- Откат настройки из истории (§8.3 «позволит откатить») — просмотр истории и откат не входят: текста UX в §7 нет.
- Пуши/напоминания, окна сна, формула бодрствования — не трогаются (пакет 2: D16–D20, ОВ-4.2 закрыт).

## Влияние / затрагиваемое

- Новые модули: `src/handlers/settings_screen.py`, `src/handlers/history.py`, `tests/` — только у dev.
- Расширяются: `src/services/settings.py` (update + запись history), `src/services/calculation.py` (агрегация недели — чистая функция), `src/services/state.py` и `src/handlers/common.py` (кнопки «📊 История за неделю» / «⚙️ Настройки» в клавиатуре — ТЗ §6), `src/texts.py` (§7.16–7.22, §7.26–7.28 дословно), `src/handlers/backfill.py` (PB-1 парный ввод, два шага), `src/db.py` (CREATE TABLE settings_history, ТЗ §9.4), `src/handlers/__init__.py` (/help, /delete_all, регистрация колбэков), `src/repositories/settings.py` (SettingsHistoryRepo).
- Техдолг пакета 2 (раздел бэклога «Техдолг пакета 2») — уборка в волне 1/4: дубли хелперов undo/events, `owner_users` SQL в scheduler.py → UsersRepo, мёртвая `total_wake`, `nap_window_text` в §7.5-ветке, локальный дубль дефолтов §5.

- Миграций данных нет; callback-схема расширяется: `history:week`, `settings:show`, `settings:edit:<key>` (ТЗ §10.3), FSM `WAIT_SETTING_VALUE` (§10.4).
