# Таблицы решений и pairwise (reference для test-case-design)

Две техники для КОМБИНАЦИЙ. Когда входных параметров несколько и правила
зависят от их сочетаний — перебор «по классам» не спасает.

## 1. Таблица решений (decision table)

Для бизнес-правил вида «если условие(я), то действие». Столбцы — комбинации
условий, строки — действия. Каждая непротиворечивая колонка = кандидат в кейс.

Пример (права × состояние страницы wiki):

| Условие / Действие | C1 | C2 | C3 | C4 |
|---|---|---|---|---|
| Пользователь — владелец? | Д | Д | Н | Н |
| Страница опубликована? | Д | Н | Д | Н |
| **Редактировать → 200** | ✓ | ✓ | — | — |
| **Редактировать → 403** | — | — | ✓ | ✓ |

Порядок: (1) выписать условия из спеки; (2) выписать действия; (3) построить
все комбинации; (4) схлопнуть колонки с одинаковым профилем действий;
(5) каждая оставшаяся колонка → кейс с трассировкой к правилу спеки.

Признак необходимости: в спеке есть «если… то…» больше чем с одним «если».

## 2. Pairwise (n=2)

Когда параметров много (клиент × браузер × локаль × роль × …) и полный
перебор N^k невыполним. Гарантия: каждая ПАРА значений встречается хотя бы
в одном кейсе.

Оценка размера: полный перебор 3×5×4×2 = 120 → pairwise обычно 10–25 кейсов.

Процедура без инструментов:
1. Параметры × значения в таблицу;
2. Пары с ограничениями выписать явно (нелегальные сочетания исключить до генерации);
3. Сгенерировать набор (pairwist / Microsoft PICT / `allpairspy` — python);
4. Каждый набор-строку → кейс; непокрытые пары не оставлять молча.

Когда НЕ нужен: параметров ≤2 (полный перебор и так мал) или большинство
комбинаций нелегальны (тогда таблица решений честнее).

## Связь с классами

Порядок применения к требованию: классы эквивалентности каждого параметра →
границы между классами → комбинации (таблица решений для правил, pairwise
для ортогональных параметров) → состояния/переходы.
