# settings-ui

## ADDED Requirements

### Requirement: Экран настроек (FR-42, FR-43, FR-47)

Бот MUST показывать экран ⚙️ Настройки (команда /settings и кнопка «⚙️ Настройки» меню §6) по §7.16: параметры в группах «Режим дня», «Ночной сон», «Бодрствование», «Прочее» с текущими значениями пользователя. Выбор параметра MUST открывать диалог §7.17 (имя параметра, текущее значение, формат). Экран и диалог MUST работать только со своим user_id; редактирование — только владелец (parent), наблюдатель — чтение.

#### Scenario: Открытие экрана из меню
- **WHEN** родитель в любом состоянии ребёнка нажал «⚙️ Настройки»
- **THEN** ответ по §7.16 с группами и текущими значениями; в sleep_events ничего не добавлено

#### Scenario: Запрос нового значения
- **WHEN** выбран параметр «Минимум бодрствования до дневного сна»
- **THEN** бот запрашивает значение по §7.17: текущее «5 ч 20 мин», формат `5:20` или `5ч20м`

#### Scenario: Изоляция пользователей
- **WHEN** родитель A меняет remind_before
- **THEN** изменились settings и история только пользователя A; данные пользователя B не тронуты

### Requirement: Валидация значений и успех (FR-44, FR-45)

Введённое значение MUST проверяться по типу параметра (длительность `5:20`/`5ч20м`/минуты; время `HH:MM`; число; физический смысл — не-отрицательность, min ≤ max). При ошибке бот MUST ответить §7.19 и MUST НЕ менять настройку. При успехе — ответ §7.18 «старое → новое», и последующие расчёты MUST использовать новое значение без перезапуска.

#### Scenario: Неразбираемый ввод
- **WHEN** в диалоге введено «полтора часа»
- **THEN** ответ §7.19; настройка не изменилась

#### Scenario: Успешная правка
- **WHEN** введено «5ч30м» при текущем 5 ч 20 мин
- **THEN** ответ §7.18 «5 ч 20 мин → 5 ч 30 мин»; окно дневного сна считается от 5 ч 30 мин

### Requirement: Логирование изменений в settings_history (FR-46)

Каждое успешное изменение параметра MUST записываться в settings_history (user_id, key, old_value, new_value, changed_at) в одной операции с обновлением settings. Неудачные попытки и отмены MUST НЕ записываться.

#### Scenario: Запись при смене
- **WHEN** wake_deadline изменён с «15:30» на «15:40»
- **THEN** в settings_history строка key=wake_deadline, old=15:30, new=15:40, changed_at — момент изменения

#### Scenario: Ошибка не логируется
- **WHEN** ввод отвергнут по §7.19
- **THEN** новых строк в settings_history нет
