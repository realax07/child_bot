## 1. Проверка обязательных исправлений F-1…F-5

### F-1 (major) — sleep_type при записи события: **УСТРАНЁН**
- D6 переписан: `sleep_type` при записи НЕ вычисляется и НЕ пишется (NULL), разметка — чистая функция при чтении/расчёте; колонка — nullable-резерв схемы (ТЗ §9.2), как и `is_merged`. Приведены ровно те аргументы, что были в finding: конец интервала неизвестен при «Сейчас», зависимость FR-9/10/11 от конца/длительности, устаревание при смене FR-24.
- Скрытая зависимость волны 2 от волны 3 устранена по существу: готовность задачи 1.3 больше не требует писать `sleep_type` (только сырые поля записи + проверка nullable-колонок), задача 2.3 дополнена «`sleep_type` при записи не вычисляется (design D6)».
- Синхронизировано по всем слоям: FR-3 + новый сценарий «sleep_type при записи не вычисляется», specs/core-storage, sdd.md §3 (схема) и §4 (алгоритм). Противоречия с FR-3/ТЗ §9.5 больше нет.

### F-2 (major) — единое правило отнесения сна к дню: **УСТРАНЁН**
- D8: одно правило — сон относится к странице дня момента НАЧАЛА сна (страница 06:00→05:59); для начала в [00:00; 06:00) — страница предыдущего календарного дня; альтернатива «по календарной дате начала» явно отклонена с обоснованием. Двусмысленность двух правил из старой D8 снята.
- FR-12 переименован и переписан, сценарий «Сон до 06:00» заменён на однозначный «Сон с началом до 06:00» (02:00 → 05:30 → страница предыдущего дня) — ровно тот случай, на который указывал finding. Синхронизировано: specs/day-boundary-logic, корневой requirements.md (введение + §2), sdd.md §4.
- Тесты добавлены: задача 3.2 — 02:00→05:30 и 23:30→02:00 (страница дня начала); задача 3.4 — отдельный тест попадания сна с началом 02:00 в сводку страницы предыдущего дня. Логика сходится с решением №2 («ночь за вчера») без взаимных противоречий.

### F-3 (major) — guard устаревших клавиатур вместо ложного инварианта: **УСТРАНЁН**
- D5: формулировка «нажатие противоречащей кнопки невозможно физически» убрана (в живых документах не осталось — grep подтверждает), заменена guard-логикой: перепроверка состояния по БД в обработчике колбэка, при противоречии — answerCallbackQuery + перерисовка актуальной клавиатуры, событие не создаётся.
- FR-6 дополнен требованием guard + новый сценарий «Устаревшая кнопка из истории чата»; specs/diary-events синхронизирован.
- Задачи: 2.2 — состояние всегда перечитывается из БД (основа guard'а); 2.3 — guard в «Сделать» и юнит-тест в «Готовности» (нажатие «😴 Заснул» из старого сообщения при спящем ребёнке → записи нет, клавиатура перерисована).

### F-4 (minor) — статус ОВ-ПО-1/ОВ-ПО-3: **УСТРАНЁН**

## 2. Новые находки (внутри диффа и на стыках)

### N-1 (minor) — корневой requirements.md §7: остаток той же ошибки нумерации, что F-5
- **Где:** requirements.md (корень), §7: «сводка без окон в Пакете 1 (№2/ОВ-ПО-2)».
- **Суть:** F-5 исправил пары «№1/ОВ-ПО-1» и «№3/ОВ-ПО-3», но пара «№2/ОВ-ПО-2» осталась: в decisions №2 — «ночь за день начала сна», ОВ-ПО-2 (сводка без окон) — из трека открытых вопросов PO-брифа, это разные нумерации. Ложная трассировка того же класса, что в F-5, в непомеченном месте. Не блокирует: F-5 в заявленном объёме устранён, ошибка не влияет на поведение.
- **Рекомендация:** убрать «№2/», оставить «(ОВ-ПО-2)» — при следующей правке корневого requirements.md.

### N-2 (note) — D8/FR-12: цитата «решение ПМ 26.10» на правило, которого в decisions-файле нет
- **Где:** design.md D8 (основание «решения №2; решение ПМ 26.10»); FR-12; задача 3.2; корневой requirements.md.
- **Суть:** отдельного решения про начала в [00:00; 06:00) в decisions/2026-10-26-pm-questions-v1-3.md нет — там только №2 (автор — продакт, не ПМ). Выбранное правило — легитимная интерпретация №2 (страница дня указана в самом №2), и по существу оно корректно, но ссылка на отдельное «решение ПМ» создаёт ложное впечатление зафиксированного решения.
- **Рекомендация:** цитировать как «интерпретация решения №2» (одна правка формулировки, не блокирует).

Прочее по диффу противоречий не внесло: D2 (пометка осознанного отклонения от ТЗ §10.3), D4 (fold=0, карта кодов тестом), D9 (`is_merged` — резерв), D11/D12 (детерминированный выбор целевого события; undo после «Изменить» не восстанавливает прежнее значение — заодно закрыта часть F-7), D13 (linkage observer→родитель — additive-миграция пакетов 2/3 — закрыта суть F-9), задача 3.3 (построение интервалов из сырых событий — закрыта суть F-8).
