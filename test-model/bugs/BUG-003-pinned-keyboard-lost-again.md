# BUG-003: прибитые кнопки пропали повторно (регресс BUG-002)

- **Дата:** 2026-10-29 (вечер, доложила Мария)
- **Источник:** Мария: «опять отвалились кнопки прибитые»
- **Severity:** S2 (повторно блокирует повседневный ввод)
- **Связь:** регресс/рецидив BUG-002 (хотфикс 5ea513d, merge 53ecc7e)

## Факты на сервере (проверено 29.10 ~19:05 UTC)

- Процесс жив: PID 3443910, старт 17:15:58 UTC 29.10, рабочий каталог чист,
  main на 87712ee — хотфикс BUG-002 (5ea513d) в коде ЕСТЬ.
- В коде НЕТ ReplyKeyboardRemove и ForceReply (grep по src пуст) — сервер
  в принципе не может убрать reply-панель: клавиатура — свойство чата на
  клиенте, снимается только явной командой удаления.
- Лог: 7 старых traceback'ов NetworkError (утреннее падение, до старта
  текущего процесса); свежих ошибок в хвосте нет.

## Гипотезы (требуют деталей от Марии)

1. Клиентский сбой Telegram после простоя бота утром (клавиатура — клиентское
   свойство; перезапуск процесса сам по себе панель не снимает).
2. Неизвестный триггер в диалоге, который мы не воспроизвели (нужен сценарий:
   после какого действия пропали).
3. Конфликт двух инстансов getUpdates (не подтвержден: второй процесс не найден).

## Немедленный workaround

`/start` — обработчик повторно присылает REPLY_PANEL_INTRO с reply-панелью,
клавиатура закрепляется заново без потери данных.

## Что нужно для root cause

- Точный момент/действие, после которого кнопки пропали.
- Пропали полностью (пустая панель) или скрылись (поля ввода нет)?
- Возвращает ли /start панель, держится ли она после следующего события.
- Клиент (iOS/Android, версия) — если воспроизводится только на одном.
