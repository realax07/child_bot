# Writing Plans: декомпозиция утвержденного спека в план задач

## Когда

После утверждения спека/requirements Заказчиком, до старта dev-работы.
Спек — вход; план — разбивка на исполняемые задачи-шаги.

## Формат задачи

Каждая задача:
- **Точно названа** (что будет после выполнения — наблюдаемый результат);
- **Самодостаточна**: исполнитель не нуждается в контексте диалога — все
  файлы/строки/ожидания в тексте задачи;
- **Малая**: завершение за один присест (часы, не дни);
- **С критерием проверки**: как убедиться, что готово (тест/смоук/факт);
- **С трассировкой**: ссылка на требование/мокап/сценарий спека.

## Порядок

1. Прочитай спек целиком; выпиши все требования с ID.
2. Сгруппируй по слоям/зонам (API/UI/данные) и зависимостям.
3. Раскладывай сверху вниз по зависимостям: сначала данные/контракты,
   потом логика, потом UI, потом полировка.
4. Для каждой задачи — точные пути файлов и границы («только эти файлы»).
5. Точные шаги проверки (команды, ожидаемый вывод) — в тексте задачи,
   не «проверить что работает».
6. Точные примеры/значения — если задача это позволяет (точные URLs,
   полные команды, готовый код примеров).

## Анти-паттерны

- «Реализовать фичу X» без файлов/критерия — отклонить собственный план.
- Задача на день+ — дробить дальше.
- Планировать точные шаги для задач, зависящих от НИЗКОуровневых
  решений, еще не принятых — такие шаги планируются на момент старта.
- Пропуск этапа проверки — задача без критерия приемки не задача.
