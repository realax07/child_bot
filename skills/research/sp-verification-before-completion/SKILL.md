# Verification Before Completion: факты до заявления «готово»

## Железное правило

Никогда не заявлять «готово/исправлено/работает/проходит» без свежего вывода
проверяющей команды в этом же цикле работы. Утверждение без факта = ложь.

## Протокол

1. **Найди команду проверки сам** (тесты/смоук/lint/health-чек), не жди
   указания. Не знаешь какую — спроси ДО заявления о готовности.
2. **Прогони и прочитай вывод ПОЛНОСТЬЮ** — не tail -1: «1 passed» может
   скрывать «9 errors» выше.
3. **Сверь результат с заявлением**: ровно те утверждения, которые
   подтверждены выводом. Остальное — «не проверено».
4. **Свежесть**: вывод из прошлой сессии/прошлого состояния дерева — не
   доказательство. Прогони заново на текущем состоянии.
5. **Доклад = факт + команда**: «тест X: 1 passed (вывод)», а не «всё
   работает».

## Анти-паттерны

- «Должно работать» — не вердикт.
- «Тесты прошли» без указания какие/сколько/когда.
- Ссылка на успешный прогон до последнего изменения кода.
- Подмена проверки смежной: «lint прошел» ≠ «тесты прошли» ≠ «фича работает».
- Проверка только счастливого пути, когда менялась обработка ошибок.
