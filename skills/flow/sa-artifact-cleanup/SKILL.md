# Чистка SA-артефактов (specs, changes, docs/ba)

Периодическая гигиена аналитического слоя: сабагент изучает проект, находит
все промежуточные (черновики, заброшенные changes, битые ссылки) и основные
артефакты (спеки, impact), проверяет их актуальность и выносит неактуальное в
archive или удаляет. ПМ ничего не ищет руками — механику дает скрипт-ручка,
семантику решает сабагент.

## Когда

- После archive_change любого крупного пакета (раз в спринт минимум)
- Перед релизом и перед запуском нового пакета
- По слову Заказчика «наведи порядок в аналитике/спеках»

## Ручка (инвентаризация)

```bash
python3 skills/factory-flow/sa-artifact-cleanup/scripts/sa_artifact_inventory.py <repo> [--stale-days 14] [--json]
```

Считает по openspec/changes/: закрытость задач, давность коммитов; по
docs/ba/ — давность и битые ссылки на несуществующие changes; осиротевшие
impact-файлы. Скрипт ничего не удаляет.

## Процедура

1. Запусти ручку на целевом репо через `terminal`. Критерий: отчет содержит
   разделы «Активные changes», «docs/ba/», «Осиротевшие impact-файлы».
2. Создай worktree-ветку `chore/sa-cleanup-<date>` от origin/main
   (работа только в worktree — урок P12/P23).
3. **Вызови сабагента через `delegate_task`** — это обязательный шаг, ПМ не
   чистит сам. Цель (подставь отчет и репо):

   > Ты — sa, уборка аналитических артефактов репо <repo>, ветка
   > <worktree>. Инвентаризация (приложена/по пути <script>) — кандидаты.
   > Для КАЖДОГО кандидата: проверь ссылки (grep по репо), git log каталога,
   > открытые ли задачи. Закрытый change без хвостов → archive (канонический
   > archive_change); заброшенный с открытыми задачами → НЕ удаляй, верни
   > вердикт «нужно решение ПМ». Битые ссылки в docs → почини или пометь.
   > Осиротевшие impact → удали после проверки, что change архивирован.
   > Прогон: openspec validate --strict. Коммит [chore], НЕ пушь. Отчет:
   > таблица кандидат → действие → причина.

4. ПМ-верификация: `git diff --stat`, выборочно открыть 2–3 решения.
   Критерий: ни один approved/спека не удален без прямого основания; все
   перемещения — git mv; validate green.
5. Пуш, PR [chore], CI, merge. Отчет Заказчику — только сводка (политика
   тишины), детали в PR.

## Запреты

- Не удалять спеки и approved-артефакты без явного основания в отчете сабагента.
- Не трогать design/tokens.html (J47, прод-эталон) и активный change текущего пакета.
- Не удалять «заброшенные, но с открытыми задачами» — это решение ПМ/Заказчика.

## Verification

- Ручка после чистки: раздел «Активные changes» без кандидатов с «ВСЕ ЗАДАЧИ
  ЗАКРЫТЫ» (все ушли в archive).
- openspec validate --strict на main green.
- git log ветки чистки: только [chore]-коммиты с git mv/удалениями из отчета.

## Pitfalls

- Каталог archive/ внутри change — неканоничен: канон — openspec/archive/.
- «Старый» ≠ «мусор»: давность без закрытых задач — сигнал разобрать, не удалить.
- docs/ba/answers_*.md — история решений Заказчика: хранить всегда.
