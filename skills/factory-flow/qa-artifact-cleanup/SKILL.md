# Чистка QA-артефактов (кейсы, тесты, отчеты)

Периодическая гигиена качества: сабагент изучает проект, находит все
промежуточные (черновики кейсов в new/, протухшие отчеты, дубли тестов,
файлы без TC-маркеров) и основные (approved-кейсы, автотесты, regress)
артефакты, проверяет актуальность относительно живых change и кода, выносит
мусор. ПМ верифицирует, руками не ищет.

## Когда

- После archive_change или закрытия пакета (хвосты в test-model/new/)
- Раз в спринт; по слову «наведи порядок в тестах/кейсах»

## Ручка (инвентаризация)

```bash
python3 skills/factory-flow/qa-artifact-cleanup/scripts/qa_artifact_inventory.py <repo> [--json]
```

Собирает: осиротевшие наборы в test-model/ (change не определен или только в
archive); пустые подкаталоги; тесты без TC-маркеров; дубли имен тестов;
разрывы покрытия (TC-ID из approved, которых нет в автотестах). Ничего не
удаляет.

## Процедура

1. Ручка через `terminal`. Критерий: разделы «осиротевшие», «без TC-маркера»,
   «дубли», «разрывы покрытия» присутствуют.
2. Создай worktree-ветку `chore/qa-cleanup-<date>` от origin/main.
3. **Вызови сабагента через `delegate_task`** — обязательный шаг. Цель:

   > Ты — qa, уборка QA-артефактов репо <repo>, ветка <worktree>.
   > Инвентаризация по ручке <script>. Для КАЖДОГО кандидата: (а)
   > test-model/new/<x> — change жив? открытые задачи? кейсы уже в approved
   > (дубликат набора)? тогда удалить дубль; change мертв и кейсы нигде —
   > удалить каталог целиком; (б) тест без TC-маркера — восстанови маркер из
   > истории/кейса, если найдешь источник; не нашел — помечай в отчете «сирота,
   > решение ПМ», НЕ удаляй сам; (в) дубли имен — сверить тела, слабый дубль
   > удалить, прогнать набор; (г) разрывы покрытия — найди кейс и отметь,
   > тест отсутствует/переименован. Полный прогон затронутых наборов green.
   > Коммит [chore], НЕ пушь. Отчет: кандидат → находка → действие.

4. ПМ-верификация: approved/ не тронут кроме явных дублей; каждый сирота-тест
   из отчета получил решение ПМ (оставить с маркером / удалить отдельно);
   прогоны green; критерий — все удаления имеют обоснование в отчете.
5. Пуш, PR [chore], CI (rule-6: у тестов обязаны быть TC-маркеры — это
   поймает сирот сразу), merge.

## Запреты

- Не удалять approved-кейсы и APPROVAL.md без решения ПМ (делегирование
  утверждения — документ Заказчика).
- Не удалять regress/reports исторических релизов (прецеденты и аудит).
- Не ослаблять ассерты, чтобы «зеленело» — чистка не меняет поведение тестов.

## Verification

- Ручка после чистки: «осиротевшие» и «дубли» — пусто; «разрывы покрытия» —
  пусто или осознанный остаток (документирован).
- CI green, полный regress-набор локально green.

## Pitfalls

- TC-маркер должен быть в docstring/тексте теста — CI (rule-6) валидирует;
  «восстановить маркер» без источника = изобрести трассировку (запрещено).
- test-model/<sub>/<change>/ может содержать частично approved-файлы — удалять
  только конкретные файлы, не каталог целиком.
- Разрыв покрытия ≠ баг: кейс может быть Should-уровня без автотеста по
  решению coverage-audit — сверяй coverage-audit.md перед действиями.
