# backfill-input

## ADDED Requirements

### Requirement: Выбор времени после события (FR-15)

После нажатия «😴 Заснул» / «☀️ Проснулся» бот MUST предлагать «🕐 Сейчас» / «⏪ Ввести время вручную» (ТЗ §4.4, §7.10). Выбор «Ввести время вручную» MUST запросить время текстом §7.11.

#### Scenario: Диалог ввода
- **WHEN** родитель нажал кнопку события
- **THEN** бот показывает §7.10 с кнопками «🕐 Сейчас» и «⏪ Ввести время вручную»

### Requirement: Форматы ручного ввода времени (FR-16)

Ручной ввод MUST принимать форматы `10:50` (сегодня), `вчера 22:30`, `08.10 7:15` (ТЗ §4.4). Нераспознанный ввод MUST вызывать ответ §7.12 с повторным запросом без создания события.

#### Scenario: Корректный ввод
- **WHEN** родитель вводит «вчера 22:30»
- **THEN** событие создано на 22:30 предыдущего календарного дня с признаком is_backfilled

#### Scenario: Ошибка формата
- **WHEN** родитель вводит «завтра 10:00» / произвольный текст
- **THEN** событие не создано, бот отвечает §7.12 и снова ждёт время

### Requirement: Глубина ввода 3 дня (FR-17)

Событие старше 3 дней (настройка «Максимальная глубина ввода», ТЗ §5) MUST отклоняться ответом §7.15 без создания записи.

#### Scenario: Слишком давно
- **WHEN** родитель вводит время 4 дня назад
- **THEN** запись не создана, бот отвечает §7.15

### Requirement: Конфликты ввода (FR-18)

Ввод, конфликтующий с уже записанными событиями (пересечение по времени или нарушение порядка sleep/wake), MUST вызывать ответ §7.13 с кнопками [Изменить] / [Отменить] (ТЗ §4.4, §7.13). «Изменить» перезаписывает целевое существующее событие с уведомлением (рекомендация ОВ-ПО-1, открытие — см. requirements §3); «Отменить» не меняет данные.

#### Scenario: Конфликт и «Изменить»
- **WHEN** записано «Проснулся» в 13:30 и родитель вводит задним числом «Заснул» на 13:30
- **THEN** бот показывает §7.13; после «Изменить» целевое событие перезаписано, данных-дубликатов нет

#### Scenario: Конфликт и «Отменить»
- **WHEN** в диалоге §7.13 выбрано «Отменить»
- **THEN** существующие события не изменены, новое событие не создано

### Requirement: Успешный ввод — сводка без окон (FR-19)

После успешного ввода задним числом бот MUST отвечать текстом §7.14 с обновлённой сводкой за день, где в этом пакете указываются только суммарные сон и бодрствование; строки окон SHALL NOT выводиться (окна — Пакет 2, interpretation note брифа AC-4).

#### Scenario: Сводка после ввода
- **WHEN** родитель успешно ввёл событие задним числом
- **THEN** бот отвечает §7.14: подтверждающая строка с временем и суммарные сон/бодрствование за день, без упоминания окон

### Requirement: «Вчера» — календарный день (FR-20)

Значение «вчера» в ручном вводе MUST означать прошедший календарный день (00:00–23:59 локального времени пользователя), а не «24 часа назад» (решения 26.10 №4). Если разрешённое время оказывается в будущем относительно момента ввода, ввод MUST отклоняться с предупреждением.

#### Scenario: Вчера поздно вечером
- **WHEN** сейчас 08:00 10 октября и родитель вводит «вчера 22:30»
- **THEN** событие создано на 22:30 9 октября

#### Scenario: Спорное время
- **WHEN** разрешённое «вчера ЧЧ:ММ» даёт момент в будущем относительно текущего момента
- **THEN** событие не создано, бот выводит предупреждение о некорректном времени
