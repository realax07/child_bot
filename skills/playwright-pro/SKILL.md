# Playwright Pro (ядро)

Систематическая база написания/диагностики web-тестов. Проектные грабли
(CDP-touch, Secure-кука на http-стенде, route_nginx) — в системном промпте
qa_automation; здесь — универсальные правила. Python-синхронный API
(sync_playwright), адаптация TypeScript-примеров источника.

## Golden Rules (10)

1. **`get_by_role()` вместо CSS/XPath** — устойчиво к смене разметки, зеркалит assistive technology.
2. **Никогда `page.wait_for_timeout()`** — заменяется на `expect(locator).to_be_visible()` или `page.wait_for_url()`.
3. **Web-first assertions** — `expect(locator)` авторетраит; `locator.text_content()` проверяет один раз и flaky на динамике.
4. **Изоляция каждого теста** — без разделяемого состояния и зависимости от порядка выполнения.
5. **baseURL в конфиге** — ноль захардкоженных URL в тестах.
6. **Retries: 2 в CI, 0 локально** — flaky проявляется там, где важен.
7. **Traces: `on-first-retry`** — артефакты отладки без замедления CI.
8. **Fixtures вместо глобалов** — разделяемое состояние через fixtures, не модульные переменные.
9. **Одно поведение на тест** — несколько связанных `expect()` в одном тесте допустимы.
10. **Мокаем только внешнее** — никогда своё приложение; мокаются сторонние API/платежи/почта.

## Приоритет локаторов

| Приоритет | Локатор | Для чего |
|---|---|---|
| 1 | `get_by_role("button", name="…")` | кнопки, ссылки, заголовки, поля |
| 2 | `get_by_label("Email")` | поля формы с label |
| 3 | `get_by_text("Добро пожаловать")` | неинтерактивный текст |
| 4 | `get_by_placeholder("Поиск…")` | инпуты с placeholder |
| 5 | `get_by_alt_text("Логотип")` | картинки |
| 6 | `get_by_title("Закрыть")` | элементы с title |
| 7 | `get_by_test_id("checkout-summary")` | когда семантики нет |
| 8 | `page.locator(".legacy")` | CSS/XPath — крайний случай |

## Common Pitfalls (топ)

1. **waitForTimeout** — медленно и flaky → замени на expect-assertion.
2. **Не-web-first assertions** — `text_content()` без ретрая на динамике → `expect(locator).to_have_text(...)`.
3. **Строгий режим**: `locator.click()` на 2+ совпадений падает → сужай локатор (`.first`, фильтр по роли/тексту).
4. **Автозакрытие контекста до assert'ов** — return контекста из fixture раньше проверок.
5. **Игнорирование консоли браузера** — подписывайся на `page.on("console")`/`page.on("pageerror")`, JS-ошибки не валят тест сами.
6. **Хардкод ожиданий текста на локали** — сервер и тест в разных локалях дают разные даты/числа.
7. **Сетевые гонки**: клик → навигация без `page.expect_navigation()` контекста.

## Flaky-таксономия (дерево решений)

```
Тест flaky
├── Падает локально с --repeat-each=20?
│   ├── ДА → TIMING/ASYNC
│   │   ├── нет await? → добавь
│   │   ├── wait_for_timeout? → замени на assertion
│   │   ├── гонка? → жди конкретное событие
│   │   └── анимация? → жди конец анимации или отключи
│   └── НЕТ → дальше
├── Проходит один, падает в сюите?
│   ├── ДА → ИЗОЛЯЦИЯ
│   │   ├── разделяемая переменная? → на тест
│   │   ├── состояние БД? → сброс на тест
│   │   └── порядок выполнения? → убери зависимость
│   └── НЕТ → дальше
├── Падает в CI, проходит локально?
│   ├── ДА → ОКРУЖЕНИЕ
│   │   ├── медленный CI? → увеличить timeout в конфиге CI
│   │   ├── разные данные/локаль? → фиксируй
│   │   └── параллельные воркеры? → раздели зоны
│   └── НЕТ → дальше
└── Падает периодически без паттерна?
    → собери trace on-first-retry, разбиар трейс; если не
    воспроизводится 20 повторов — пометь @flaky с issue-ссылкой,
    НЕ оставляй молча красным.
```

## Anti-patterns (реестр)

- Селекторы по автогенерируемым классам (`css=xyz123`) — обрыв при пересборке.
- Тест зависит от данных предыдущего теста — изоляция нарушена.
- Один гигантский тест «весь сценарий целиком» — падение в середине оставляет непроверенный хвост.
- Скриншот-диффы без стабильного окружения — flaky по отрисовке.
- Скип без issue-ссылки — «забытый» тест навсегда.

## Инструмент (scripts/)

**`scripts/locator_audit.py`** — аудит локаторов web-тестов: сколько «сырых»
локаторов в каждом файле, кто не использует Page Objects (кандидаты на
конвертацию), где CSS/XPath вместо семантических локаторов (приоритет из
этого скилла). Прогон после каждой web-задачи — рост числа сырых локаторов
в файле = сигнал тянуть локаторы в PO, а не размножать.

```bash
python skills/playwright-pro/scripts/locator_audit.py tests/web
python skills/playwright-pro/scripts/locator_audit.py tests/web --strict  # для CI-привычки
```
