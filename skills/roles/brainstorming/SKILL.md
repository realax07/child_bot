# Brainstorming: проработка замысла до постановки

Первая фаза elicitation БА (перед `requirements-elaboration`). Цель — понять
ЗАМЫСЕЛ, а не закодировать первую формулировку. Выход фазы — проверенное
понимание, на котором требования пишутся без догадок.

## Когда

ДО создания `requirements.md`/постановки задачи — при любой новой фиче,
изменении поведения или противоречивых вводных.

## Процедура

1. **Прочитай контекст**: существующие артефакты (мастер-спеки
   `openspec/specs/`, мокапы, PRODUCT_BACKLOG, решения Заказчика) — сначала
   факты, потом вопросы. **Grill-дисциплина (J45, из grill-me): если ответ
   можно найти в коде/артефактах — ищи сам, не спрашивай Заказчика.**
2. **Проверь понимание одной формулировкой**: «Правильно ли я понимаю, что …»
   — пересказ своими словами. Только после подтверждения — углубляться.
3. **Вопросы по намерению** (по одному кластеру, не лавиной):
   - Какую проблему пользователя это решает? Кто и когда упирается в неё?
   - Что из уже сделанного затрагивается? Что ломать нельзя?
   - Как выглядит «готово» с точки зрения пользователя (наблюдаемое поведение)?
   - **Один вопрос за ход + рекомендованный ответ** (J45, grill-me): «Делаем X
     (основание Y)?» — голое «что думаете?» лениво; Заказчик отвечает по пунктам.
4. **Альтернативы**: минимум 2 варианта решения с trade-off (просто/гибко,
   быстро/правильно). Заказчик выбирает осознанно.
5. **Ограничения и границы**: что НЕ делаем в этой итерации (anti-scope).
6. **Итог**: резюме замысла + выбранный вариант + anti-scope — в постановку.
   Неразрешенные вопросы — явно списком «открытые вопросы», не прятать в
   допущения. Дерево решений проходи depth-first: ветку закрой до открытия
   следующей; зависимые вопросы — в порядке зависимости.

## Правила

- Вопросы Заказчику — нумерованным списком (конвенция проекта ОВ-N).
- Оборванные вводные — не додумывать: спросить.
- «Интерпретация ПМ» в постановке — помечать явно.
- Не выпускать постановку с открытыми вопросами, влияющими на оценку.
- Цитируй источник каждого требования (мокап/спека/слово Заказчика).
- Лимит раундов вопросов — из системного промпта роли (обычно 2).
