# Шаблон делегации задачи сабагенту (контекст D1)

> Чеклист сборки `goal` для `delegate_task`. Цель: одинаковая полнота передач при минимальном объеме текста — сабагент не видит диалог ПМ, только этот текст и файлы репозитория. Заполняется ПМ на каждую делегацию; для повторных доработок цикла ревью — только блоки 5–7.

## Чеклист сборки goal

0. **Заголовок flow (J43/J43.1)** — ПЕРВАЯ строка goal для конвейерных делегаций (обязателен, проверяет плагин flow-enforcer):
   `flow: flow=<1-5> role=<роль> repo=<путь> scope=<идентификатор> [paths=<путь1,путь2,...>] [kind=docs|product]`
   scope по флоу (J43.1): **Флоу 1** — change-id (`add-widget`); **Флоу 2** — bug-id формата `BUG-NNN` (репорт `test-model/bugs/BUG-NNN.md`); **Флоу 3** — incident-id (формат любой, обязателен); **Флоу 4** — chore-slug (легкий план `PLAN-<slug>.md` в корне); **Флоу 5** — slug экспресс-задачи.
   `paths` — относительные пути задачи через запятую; попадают в flowctl prepare как `--path` (BUG-AF-RECHECK-001: отсутствие путей ≠ docs-only — продуктовая задача без путей блокируется `PATHS_MISSING`). `kind` — тип задачи: `docs` (облегченный маршрут, пути не обязательны) или `product` (пути обязательны); kind не указан — WARNING и трактовка как product (без путей — `PATHS_MISSING`).
   Для dev_task (Флоу 1) добавь также `task: <id задачи tasks.md>`. Старый формат без `flow=` (`flow: role=R repo=P change=C`) трактуется как Флоу 1 с WARNING — мигрируй на новый. Очевидные ошибки (`flow=9`, пустой scope, Ф2 не `BUG-NNN`, неизвестный kind) блокируют делегацию (`FLOW_MARKER_INVALID`) в любом режиме. Без заголовка делегация блокируется в strict-режиме энфорсера (см. plugins/README.md); обход — только `flow: bypass --by customer` при действующей записи в реестре решений Заказчика (`~/.hermes/state/flow-bypass-decisions.json`).
1. **Роль** — путь к системному промпту: `agents/<роль>_agent.md` (сабагент читает сам, не копируем в goal).
2. **Правила** — пути: `AGENTS.md` фабрики, `contracts/artifact_contract.md` (номер контракта: вход/выход), скилл роли при нестандартной задаче.
3. **Задача** — что сделать; артефакты-входы (точные пути); артефакт-выход (точный путь). Для партионного ревью (H3, >12 кейсов) — явный список файлов партии и её номер.
4. **Зона записи** — из таблицы зон (`agents/README.md`); «запись вне зоны запрещена»; **push НЕТ**.
5. **Решения Заказчика** — дословные цитаты с номерами (ОВ-N / «интерпретация ПМ» + основание), только те, что влияют на задачу.
6. **Отчет** — пути измененных/созданных артефактов, результаты самопроверок (ворота: `openspec validate --all --strict`, `flow_check`), вопросы/эскалации списком.
7. **Изоляция** — «контекста диалога у тебя нет; всё необходимое — в файлах и этом тексте; недостающее — эскалация, не домысливание».
8. **Параллель** — «активные параллельные сессии и их зоны: <список или "нет">» — оркестратор заполняет всегда (AGENTS.md правило 10: параллель только при непересекающихся зонах). Источник: `~/.hermes/state/active_sessions.json` (вне git).
9. **Проверка** — команда/сценарий воспроизведения для ревьюера (smoke-скрипт, curl-набор, шаги). Без этого ревьюер вернет задачу (skills/code-review шаг 1). Для прогонов тестов: **очищай унаследованные env стенда** (`env -u EKOTOV_WIKI_BASE_URL -u EKOTOV_WIKI_DB_PATH` — имена стендовых env проекта) — фоновые env завершенных сессий отключают автоподъем стенда и дают ложные ERR_CONNECTION_REFUSED (E6).

## Правила экономии контекста

- goal ≤ ~2500 символов на типовую задачу; ссылки на файлы вместо пересказа их содержимого.
- Цитаты Заказчика — только дословно значимые; пересказ запрещен (искажает решение).
- Для цикла доработки: передавать только диф-границу (какие файлы/кейсы править) + путь review-файла, не всю исходную задачу.
- Статус длительных работ ПМ ведет в `PLAN.md` (см. ниже), в goal — только текущая задача.

## Журнал делегаций (PLAN.md)

Каждая делегация фиксируется ПМ одной строкой в `PLAN.md` (раздел «Журнал делегаций»):

```
- deleg_<id8> | роль | задача (кратко) | статут: запущена/одобрено/возврат | ключевой результат (коммит/артефакт)
```

Назначение: при потере контекста (компакция, новая сессия) ПМ восстанавливает картину из PLAN.md, а не из памяти; журнал append-only, правило 7 AGENTS.md.

## Проверка размера (J31)

Перед диспатчем dev-делегации оцени: [M] с ≥2 под-областями (код+стили+разметка+тесты) — режь на [S]+[S] (реализация / полный тест-файл отдельно). Циклическая отладка playwright в составе [M] = гарантированный max_iterations. Сабагент держит WIP-чекпоинт каждые ~15 итераций (правило в dev_agent.md).
