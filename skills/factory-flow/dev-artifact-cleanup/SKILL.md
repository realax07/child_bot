# Чистка dev-артефактов (код, ветки, worktrees, скрипты)

Периодическая гигиена кодовой базы: сабагент изучает проект, находит
промежуточные артефакты разработки (протухшие worktrees, влитые ветки,
мертвые скрипты/модули, накопленные TODO) и основные (живой код), проверяет
актуальность каждого кандидата и выносит мусор. ПМ решает по отчетам, руками
не ищет.

## Когда

- После merge крупного пакета (поэтому скапливаются /tmp/wt-*)
- Раз в спринт; по слову «наведи порядок в коде/ветках»

## Ручка (инвентаризация)

```bash
python3 skills/factory-flow/dev-artifact-cleanup/scripts/dev_artifact_inventory.py <repo> [--json]
```

Собирает: worktrees вне репо с давностью; ветки, влитые в HEAD; TODO/FIXME/XXX
(топ файлов); скрипты scripts/ без ссылок; модули backend/app без импортов
(эвристика). Ничего не удаляет.

## Процедура

1. Ручка через `terminal` на целевом репо. Критерий: пять разделов отчета
   присутствуют.
2. Worktrees и влитые ветки — быстрые победы: ПМ сам `git worktree remove`
   (сначала `git -C <wt> status` — чисто ли) и `git branch -d`. Это не код —
   сабагент не нужен.
3. Кодовые кандидаты (мертвые скрипты/модули, TODO-рефакторинг) —
   **обязательный вызов сабагента через `delegate_task`**. Цель:

   > Ты — dev, уборка артефактов репо <repo>. Создай worktree-ветку
   > chore/dev-cleanup-<date> от origin/main. Инвентаризация по ручке
   > <script> (отчет приложен). Для КАЖДОГО кандидата: докажи мертвость
   > (grep ссылок, imports, git log ≥ 30 дней), затем удали. После каждого
   > блока удалений — полный прогон тестов проекта (количество и команда из
   > conftest/README); любое падение → откат блока и вердикт «живой, НЕ
   > удалять». TODO — не удаляй, сгруппируй в таблицу (файл → суть → куда).
   > Коммит [chore] по блокам, НЕ пушь. Отчет: кандидат → вердикт → действие.

4. ПМ-верификация: дифф только удаления/простые правки; тесты green в отчете
   сабагента продублировать локальным прогоном; критерий — каждый удаленный
   файл имеет в отчете строку-обоснование.
5. Пуш, PR [chore], CI, merge. Не слитые при деплое ветки удалять после merge.

## Запреты

- Не удалять модуль, если на него ссылается тест, спека, impact или конфиг деплоя.
- Не гасить продовые контейнеры/стек ради чистки (3x-ui — не трогать вовсе).
- Не удалять TODO из ТЗ/спек — только из кода и только с вердиктом сабагента.

## Verification

- Ручка после чистки: разделы worktrees/merged — пусто или осознанный остаток.
- Полный тест-прогон green; CI PR green.
- `git worktree list` — только активные рабочие.

## Pitfalls

- Влитая ветка может держать незалитые коммиты: `branch -d` (не `-D`) сам
  откажется — это защита, не помеха.
- Модуль без импортов может быть точкой входа (uvicorn target, воркер) —
  сабагент обязан проверить способ запуска (README, deploy, compose).
- /tmp-worktrees переживают /tmp-чистку хоста: сверять с `git worktree list`,
  а не с ls /tmp.
