## Затрагиваемое

- Модули (создаются): `src/services/recommendation.py`, `src/services/scheduler.py`, `src/handlers/hint.py`, `src/handlers/reminders.py` (или интеграция шедулера в `src/main.py`), `tests/**` (новые + правки существующих).
- Модули (расширяются без смены существующего поведения): `src/services/calculation.py` (только новые функции), `src/texts.py` (§7.6–7.9 дословно + сборка окон в подтверждения), `src/handlers/__init__.py` (регистрация `status:show`), `src/handlers/events.py`, `src/handlers/backfill.py` (строка окна в подтверждениях), `src/main.py` (старт/стоп планировщика).
- Миграций БД нет: `remind_before` и `target_nap_duration` засеяны пакетом 1 (design D14 пакета 1); `sleep_type` CHECK-миграция — Пакет 3.
- Сквозные: единый CalculationService для подсказок, подтверждений и напоминаний (ТЗ §4.6 «логика та же»); callback `status:show` — по ТЗ §10.3, в пакет 1 не входил.

## Допущения

- Часы сервера = локальное время пользователя не требуется: расчёты на naive-временах в TZ пользователя (D4 пакета 1); «сейчас» берётся как `datetime.now(TZ)` на границе сервиса.
- Порог мягкой отметки незавершённого сна = ровно `target_nap_duration` (90 мин) — «слишком долго» без доп. запаса; запас +10 мин — только в ОВ-4.1 (WAITING_PRODUCT).
- Прогноз конца дневного сна для §7.8/§7.9-проверок = начало + `target_nap_duration`; если ребёнок спит дольше — прогноз уточняется при следующем событии.
- Приоритет якорей в D18 (ночь > 15:30 > дневное окно) — решение ПМ по духу ТЗ §3.6 («ночное — около 22:00/22:30» в обоих отклонениях); продакт может переопределить.
