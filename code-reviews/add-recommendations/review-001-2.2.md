## Проверка 2: guard устаревшего callback (design D5)

- Образец (`events.py`, `is_stale_callback`): состояние перечитывается из БД на каждое нажатие, противоречащее событие не создаётся. У подсказки противоречия быть не может (валидна в обоих состояниях), поэтому guard сведён к перечитыванию: `_current_status` читает `list_raw_events` + `SettingsService.get_all` при каждом вызове, без кэша — это образец D5 в применимой части; ветки deny/перерисовки по design не требуются (документировано в шапке `hint.py`).
- Проба: нажатие бодрствующему → внешний sleep 13:30 МСК → время 14:15 МСК → повторное нажатие СТАРОЙ кнопки — ответ «Сон идёт с 13:30 (уже 45 мин)» по СВЕЖЕМУ состоянию, записей ровно 3 (совпадает с TC-HINT-005).
