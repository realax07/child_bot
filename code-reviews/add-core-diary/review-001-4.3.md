## Собственные контрольные случаи (сверх TC-карты, все выполнены против кода a7a1c2f)

1. **Глубина 0:** `parse_time_input("10.10 07:59", MSK, now, max_age_days=0)` → TOO_OLD (1 минута назад уже отвергается); ровно `now` → datetime проходит (строгое неравенство). Осмысленный крайний случай: depth=0 = «задним числом нельзя».
2. **Глубина 1 + «вчера»:** при now = 08:00.10 «вчера 22:30» (9.5 ч назад) → проходит; «вчера 07:00» (25 ч назад) → TOO_OLD. Подтверждает физическую (не календарную) семантику глубины: «вчера» вечером ещё можно, «вчера» рано утром уже нет — соответствует FR-17 в физическом чтении, зафиксировать в design (note 1).
3. **DST-переход в окне 3 дней** (Europe/Berlin, переходы 25.10.2026 fall-back и 29.03.2026 spring-forward): fall-back — «25.10 12:00» при now «28.10 12:00» → ровно 3d UTC, проходит; «25.10 13:00» при now «28.10 13:00» → ровно 3d, проходит (оба момента по одну сторону перехода — часы взаимно сокращаются). Spring-forward — «28.03 12:00» при now «31.03 12:00» → фактические 2d23h (D2: `2 days, 23:00:00`), проходит. Асимметрия note 1 подтверждена: в TZ с DST граница «3 дня» плавает на ±1 ч; для дефолтной Moscow-аудитории неактуально.
