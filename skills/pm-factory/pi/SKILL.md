# Pi — дешевый исполнитель за адаптером

Pi (pi.dev, `@earendil-works/pi-coding-agent`, npm) — внешний CLI-агент.
В конвейере играет роль **исполнителя механических задач** на дешевой модели
(glm-5.3-flash через zai-glm провайдер, конфиг `~/.pi/agent/models.json`,
chmod 600). Оркестратор — всегда Hermes: делегации, ворота, верификация ПМ.

## Когда использовать (а когда нет)

**Да:** зеркала файлов/скиллов, тест-гигиена по готовому чек-листу,
массовые механические правки (переименования, бампы, ротация контента),
форматирование, простые монотонные фиксы с понятным критерием.

**Нет:** архитектура, хитрые дебаги, прод-логика, задачи без четкого
критерия приемки — там Hermes-сабагенты на основной модели.

## Контракт вызова

1. ПМ/сабагент создает worktree-ветку (`-b chore/...` от origin/main).
2. Запуск через `terminal`:

```bash
cd <worktree> && pi --provider zai-glm --model glm-5.3-flash --no-session \
  -p "<задача: шаги, критерий, 'не пушь'>"
```

3. **Верификация ПМ обязательна** (урок: сабагенты самовольно пушат — Pi не
   исключение): `git diff --stat`, byte-diff для зеркал (`diff -r`), прогон
   тестов/скриптов, отсутствие посторонних файлов.
4. Пуш/PR — ПМ или явное разрешение в промпте.

## Стоимости/лимиты

- Модель flash-класса, ничего тяжелее (решение Заказчика 2026-10-28).
- Ключ zai — отдельный для Pi, в `~/.pi/agent/models.json` (не в git).
- Расширения/пакеты Pi — только собственные; чужие `pi install` запрещены.

## Pitfalls

- pi читает модели из `<agent-dir>/models.json` = `~/.pi/agent/models.json`
  (НЕ `~/.pi/models.json`).
- zai-ключ без активного GLM Coding Plan дает 429 «Insufficient balance» —
  ключ должен быть из аккаунта с планом.
- `-p` (print mode) = «команда → результат»; для интерактивных сессий не
  годится, длинные задачи дробить.
