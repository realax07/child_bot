## Собственные атаки (все выполнены против кода `3d8b30e`, скрипт вне репо)

1. **Двойной ввод wake:** sleep −5ч, wake −3ч (пара закрыта), backfill wake −1ч → конфликт (сосед-wake, D11); после штатного закрытия незакрытого sleep повторный wake − тоже конфликт. «Бесплатных» вторых wake нет.
2. **Wake РОВНО в start незакрытого sleep** → §7.13, цель — сам sleep (точное совпадение). Осознанное решение, оценено корректным (Note 1).
3. **Wake между закрытой парой и незакрытым sleep** (sleep −6, wake −4, sleep −2; wake на −3ч) → конфликт с wake −4ч: вставка даёт «два wake подряд» — штатное нарушение порядка D11, НЕ регрессия пропуска (первоначальная гипотеза атаки «не конфликт» — ошибочна; докстринг корректно ограничивает безконфликтный случай отсутствием нарушения порядка).
4. **Незакрытый sleep + ввод sleep** (−2ч, ввод −1ч) → §7.13, цель sleep (двойное засыпание ловится, скидка только для wake).
5. **Испорченный «двойной sleep» с разными timestamp** (sleep −6, sleep −2; wake −1) → конфликт с ПЕРВЫМ sleep: скидывается только хвостовой интервал, тихой записи нет (см. Note 2 про идентичные timestamp).
6. **Wake == start ЗАКРЫТОЙ пары** → §7.13, цель sleep пары — точное совпадение сохранено везде.
7. **Штатное закрытие + немедленный контроль:** sleep −3ч; wake −1ч → None (пара создана); повторный wake −30 мин → конфликт. Пропуск срабатывает ровно один раз, на незакрытом хвосте.
8. **SQL-инъекция через kind** (`"sleep'); DROP TABLE sleep_events;--"`) → `ValueError` до БД, таблица цела; все запросы репозитория параметризованы.
