# Рубрика серьезностей (reference для case-review / code-review)

Единая шкала замечаний ревью конвейера. severity_counter.py проверяет
пороги вердикта по этим же меткам.

## blocker

- Нарушение спеки/контракта: поведение расходится с design.md/спекой домена.
- Слом интеграции: падают существующие сценарии, регресс подтвержден.
- Безопасность/данные: authz-дыра, инъекция, потеря данных, необратимая миграция.
- **1 blocker = BLOCK** (возврат, merge невозможен до фикса).

## major

- Дефект в периметре задачи, не ломающий соседей: неверная валидация, непокрытый
  сценарий спеки, рассинхрон токенов design/tokens.html ↔ app.css.
- Нарушение процессного контракта: тесты без TC-трассировки (rule 6),
  несанкционированный выход за зону задачи.
- **≥3 major = CONCERNS** (возврат на точечную доработку; 1–2 — на усмотрение
  ревьюера с явным перечнем).

## minor

- Качество без дефекта поведения: дублирование, имя не по конвенции, magic-число
  число без константы, пропущенный комментарий к нетривиальному инварианту.
- Не блокирует merge; фикс — в этой же задаче по возможности или в BACKLOG.

## info

- Вопросы, наблюдения, предложения (без требования изменения).
- В вердикт не влияют.

## Дисциплина

- Каждое замечание: ID (DV-N/N-N/M-N), файл/строка, что ожидалось vs что есть.
- Дубликат замечания из прошлого ревью после фикса — с пометкой «повтор»
  (повтор blocker/major после RETURN = эскалация ПМ).
- Замечание поймано 2+ adversarial-персонами (code-review §4b) — severity
  повышается на ступень.
